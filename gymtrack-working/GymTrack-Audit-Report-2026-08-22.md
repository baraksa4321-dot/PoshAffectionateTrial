# My Routine — דו״ח ביקורת מלא

**תאריך:** 22 באוגוסט 2026  
**היקף:** סקירת מקור, מיגרציות Supabase, Build/Lint, Preview חי במסך מובייל, לוגי
הדפדפן והבדיקות האחרונות שבוצעו בפרויקט.

## סיכום מנהלים

האפליקציה במצב טוב כ־MVP מתקדם: היא נבנית בהצלחה, עולה ב־Preview, כוללת הפרדה
בין מרחב אישי וניהולי, אימונים, תזונה, ספריות, טיימר מנוחה, היסטוריה,
Supabase ו־Owner/Coach/Client.

עם זאת, היא **לא עברה עדיין QA מלא עם חשבונות Supabase אמיתיים**. לפני הפצה
רחבה מומלץ לבצע סבב קצר עם משתמש חדש, משתמש קיים, Coach ו־Owner. יש גם כמה
ליקויים ידועים שאינם חוסמים את ה־Build אך עלולים להשפיע על משתמשים אמיתיים.

## ממצאים לפי חומרה

### P0 — חוסם הפצה

**לא נמצא P0 בקוד או ב־Build.**

### P1 — גבוה

#### 1. הרשאות ופרופילים לא נבדקו עם חשבונות אמיתיים

המערכת כוללת RLS, RPCs והפרדה בין Owner, Coach ו־Client, אך לא בוצע סבב
בדיקה חי מול משתמשים אמיתיים. חובה לבדוק:

- Client אינו רואה מתאמן אחר.
- Coach רואה רק מתאמנים משויכים.
- Owner יכול לנהל את המרחב הניהולי.
- משתמש אינו יכול לשנות לעצמו Role.
- משתמש חדש מאומת מקבל פרופיל ונטען לאפליקציה.
- משתמש קיים ללא `profiles` מקבל פרופיל בסיסי.
- Logout מחליף את נתוני המשתמש ומנקה cache מקומי.

**המלצה:** לבצע מטריצת בדיקות עם ארבעה חשבונות: משתמש חדש, Client, Coach,
Owner, כולל שני דפדפנים ושני מכשירים.

#### 2. מיגרציות Supabase צריכות להיות מסונכרנות עם סביבת הייצור

קיימות מיגרציות בקוד, כולל מיגרציה חדשה עבור `profiles.gender`, אך לא בוצעה
השוואה מלאה בין סכמת הפיתוח לסכמה החיה. פרסום הקוד בלי החלת מיגרציות חסרות
עלול ליצור שגיאות runtime.

**המלצה:** לפני Publish לבדוק ב־Supabase את קיום הטבלאות, העמודות, ה־RLS,
הפונקציות וה־grants של המיגרציות האחרונות. לא לאפס או למחוק נתונים.

#### 3. קרדיו ומשקל עדיין מדווחים כחסרים ב־Preview

בלוגי ה־Preview נראו:

- `public.body_weight_logs is unavailable`
- `public.cardio_logs is unavailable`
- `Cardio logs lookup failed: Could not find the table 'public.cardio_logs'`

האפליקציה אינה נעצרת בגלל זה, וזה תואם את ההחלטה שטבלאות אלה אופציונליות,
אבל הסנכרון עדיין מחזיר אזהרה ואף נכשל עבור אותו סבב סנכרון. אם היסטוריית
משקל וקרדיו אמורה להישמר בענן, צריך להחיל את המיגרציות ולבדוק כתיבה/קריאה.

**המלצה:** להחיל את מיגרציות ה־body weight וה־cardio, או לעטוף גם את פעולות
הסנכרון כך שהיעדר טבלה אופציונלית לא ייצור שגיאת סנכרון חוזרת.

### P2 — בינוני

#### 4. התאמת זכר/נקבה עדיין אינה מלאה בכל האתר

נוספה בחירת **גבר / אישה** בהרשמה, והערך נשמר ב־Auth metadata ונקרא בעת
טעינת הפרופיל. עם זאת, חלק גדול מהטקסטים בממשק עדיין כתובים בלשון נקבה
קבועה, למשל “בחרי”, “הוסיפי”, “שמרי”, “לחצי” ו־“צאי”.

**המלצה:** לרכז מילים ופעלים תלויי־מגדר במילון UI או ב־helper, ולהעביר אליו
את מסכי הבית, התזונה, התוכניות, התרגילים והניהול. לאחר מכן לבדוק את אותו
מסך פעם אחת במצב גבר ופעם אחת במצב אישה.

#### 5. טופס ההתחברות חסר `autocomplete`

בצילום מובייל חי הופיעה אזהרת דפדפן:

> Input elements should have autocomplete attributes

המשמעות היא שמילוי אוטומטי של אימייל וסיסמה עלול לעבוד פחות טוב במובייל.

**המלצה:**

- לאימייל: `autocomplete="email"`
- להתחברות: `autocomplete="current-password"`
- להרשמה: `autocomplete="new-password"`
- להוסיף `name` סמנטי לשדות.

#### 6. ה־Preview מציג אזהרות CSS של Tailwind

בלוגי Vite מופיעות אזהרות `Unknown at rule` עבור `@theme` ו־`@utility`.
ה־Build מצליח והעיצוב נטען, לכן זו אינה תקלה חוסמת, אבל היא יוצרת רעש
בלוגים ומקשה לזהות תקלות אמיתיות.

**המלצה:** לבדוק אם אזהרות אלה מגיעות מהשרשרת של Tailwind/Vite ולהגדיר את
המעבד המתאים או לסנן אותן רק אם הן ידועות ולא משפיעות על ה־CSS.

#### 7. בדיקות אינטראקטיביות מלאות עדיין חסרות

לא קיימת כרגע חבילת בדיקות Browser/E2E שמאמתת:

- הרשמה, אימות מייל, התחברות ואיפוס סיסמה.
- פתיחת וסגירת Overlay בכל מסך.
- יצירת תוכנית, יום אימון ותרגילים.
- טיימר מנוחה, עצירה, המשך, דילוג ורענון.
- תפריט מתוכנן לעומת יומן אכילה בפועל.
- שמירת משקל וקרדיו אחרי רענון.
- התנהגות ב־375, 390, 402 ו־430 פיקסלים.

**המלצה:** להוסיף לפחות smoke tests ידניים מתועדים או E2E בסיסי לפני שינויי
פיצ'רים נוספים.

### P3 — נמוך

#### 8. תמונת השיתוף היא favicon

תגיות Open Graph ו־Twitter הוגדרו עם שם האתר **My Routine**, תיאור ולוגו,
אבל התמונה מפנה ל־`/favicon.ico`. חלק מהרשתות החברתיות מעדיפות PNG/JPG
בכתובת ציבורית מלאה ובגודל 1200×630.

**המלצה:** ליצור תמונת שיתוף ייעודית עם הלוגו והכיתוב My Routine, להגדיר
`og:image` לכתובת production מלאה, ולבדוק שליחה ב־WhatsApp וב־Telegram.

#### 9. קיימות אזהרות Fast Refresh

`npm run lint` מסתיים ללא שגיאות, עם 6 אזהרות קיימות על קבצי UI שמייצאים גם
קומפוננטות וגם ערכים נוספים. אין לכך השפעה ידועה על משתמש הקצה.

**המלצה:** לפצל exports של constants/helpers מקבצי הקומפוננטות אם רוצים
Lint נקי לחלוטין.

## מה נבדק ועבר

- `npm run build` — עבר בהצלחה.
- `npm run lint` — עבר עם 0 שגיאות ו־6 אזהרות בלבד.
- `git diff --check` — ללא שגיאות whitespace.
- Workflow של ה־Preview רץ.
- מסך התחברות נטען במובייל.
- קיימת אנימציית טעינה במקום טקסט “בודקת את החיבור המאובטח”.
- קיים טיימר מנוחה קבוע במסך האימון.
- קיימת בחירת מגדר בהרשמה.
- קיימת התאוששות כאשר פרופיל Supabase חסר.
- מטא־דאטה של My Routine, favicon, manifest ו־Open Graph מוגדרים.
- אין שימוש ב־service-role key בקוד הלקוח.

## מה לא ניתן לאשר מה־Preview בלבד

- שהמיילים באמת מגיעים ושהקישורים מפנים לכתובת production נכונה.
- שכל המיגרציות כבר הוחלו על Supabase החי.
- שכל כללי ה־RLS מונעים גישה בין משתמשים.
- שכל כתיבות ההיסטוריה נשמרות לאחר Logout, Login ורענון.
- שה־OG image מוצג נכון בכל רשת חברתית.
- שהטקסטים מתחלפים במלואם לזכר/נקבה בכל מסך.

## רשימת בדיקה לפני הפצה

1. ליצור משתמש חדש ולבחור אישה.
2. לאמת מייל, להתחבר ולרענן.
3. לחזור על הפעולה עם בחירת גבר ולבדוק את השפה.
4. לבדוק משתמש קיים ללא `profiles`.
5. לבדוק Client, Coach ו־Owner עם נתונים נפרדים.
6. ליצור תוכנית, יום אימון, תרגיל ותפריט.
7. להתחיל אימון, לסמן סט, לבדוק טיימר ולרענן.
8. לשמור משקל וקרדיו ולבדוק שהנתונים חוזרים.
9. לשלוח קישור ב־WhatsApp/Telegram ולבדוק שם ולוגו.
10. לפתוח במכשיר מובייל אמיתי ולבדוק שדות, גלילה, Overlay וכפתורים.
