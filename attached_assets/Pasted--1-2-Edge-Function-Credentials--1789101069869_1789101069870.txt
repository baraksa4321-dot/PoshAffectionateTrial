# פרומפט ביצוע — שלבים 1+2: סנכרון Edge Function ואימות Credentials

## הקשר
בוצע אודיט מלא למערכת ה-push notifications (ראה `push-notifications-fix-plan.md`). האודיט אישר:
- הפונקציה שרצה בפרודקשן (`send-fcm-notification`, v16) ישנה מהקוד המקומי.
- אין אימות runtime שה-credentials של Firebase (`FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_PROJECT_ID`) תקינים בפועל.
- לא בוצע עד כה שום שינוי בקוד, במסד, ב-secrets או בקונפיגורציה.

המשימה שלך: לבצע בפועל את שני השלבים הבאים, ולדווח תוצאה אמיתית — לא הנחה.

---

## שלב 1 — סנכרון הפונקציה בפרודקשן עם הקוד המקומי

1. הפק diff מלא בין `send-fcm-notification` כפי שהיא פרוסה כרגע לבין הגרסה בריפו המקומי.
2. הצג את ה-diff במלואו לפני שאתה עושה כל דבר אחר — אל תניח שאתה יודע מה השתנה.
3. אם ה-diff תקין ותואם את הצפוי (הוספת `deepLink`, הגבלת קואצ'ים, payload מעודכן) — פרוס מחדש (`supabase functions deploy send-fcm-notification`).
4. אחרי הפריסה, ודא ותעד:
   - מספר הגרסה החדש (אמור לעלות מ-v16).
   - JWT verification עדיין מופעל.
   - הרצת קריאה בודדת לפונקציה עם משתמש טסט, והצגת ה-payload שחוזר בפועל.

**דיווח נדרש:** מספר גרסה לפני/אחרי + תוכן ה-diff שהופעל + תוצאת קריאת הטסט.

---

## שלב 2 — אימות Firebase credentials בפועל

1. בדוק שקיימים ב-Supabase secrets: `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_PROJECT_ID`. **אל תדפיס את הערכים עצמם** — רק אשר שהם קיימים ותקינים בפורמט (למשל שה-private key הוא PEM תקין).
2. ב-Firebase/Google Cloud Console, ודא:
   - Firebase Cloud Messaging API מופעל בפרויקט.
   - ה-service account המשויך ל-credentials מחזיק הרשאה לשליחת FCM.
3. הרץ טסט ריצה אמיתי: קריאה שמבצעת את שלב ה-OAuth exchange מול Google (יצירת JWT מה-service account → בקשת access token), ובדוק את קוד התגובה בפועל.
4. אם יש כשל — דווח את קוד השגיאה המדויק (401/403/400 וכו') ואת המשמעות שלו (private key שגוי / role חסר / project ID לא תואם), ואל תנסה "לתקן בניחוש".

**דיווח נדרש:** תוצאת קריאת ה-OAuth בפועל (הצלחה עם access token תקף, או קוד שגיאה מדויק).

---

## כללי עבודה מחייבים
- אל תסמן שום סעיף כ"הושלם" בלי תוצאה קונקרטית (מספר גרסה, קוד תגובה, תוכן לוג).
- אם משהו נכשל — עצור, דווח בדיוק מה נכשל, ואל תמשיך לנחש תיקונים בלי אישור.
- אל תיגע בשלבים 3–5 מהתוכנית המלאה (רישום טוקנים אמיתיים, טסט E2E, תיקוני אמינות) — אלה מחוץ לתחום הפרומפט הזה.
- בסיום, סכם: מה בוצע בפועל, מה ההוכחה לכל טענת הצלחה, ומה (אם בכלל) נשאר פתוח לפני המעבר לשלב 3.
