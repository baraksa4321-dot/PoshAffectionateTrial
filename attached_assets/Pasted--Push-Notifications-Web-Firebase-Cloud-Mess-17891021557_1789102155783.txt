אני רוצה שתסיים ותממש באתר שלי מערכת Push Notifications אמיתית עבור Web, באמצעות Firebase Cloud Messaging (FCM) + Supabase.

## מצב נוכחי בפרויקט (לידיעתך לפני שאתה מתחיל)
- קיימת כבר Edge Function בשם `send-fcm-notification`, פרוסה בגרסה v17, מעודכנת ותואמת לקוד המקומי (diff נקי).
- קיימת טבלת `push_tokens` ב-Supabase עם RLS פעיל, אבל **היא ריקה כרגע — אין אף שורה בה**.
- קיימת כבר תשתית client-side ל-Firebase Messaging, VAPID key, ו-Service Worker (`public/sw.js`) — תבדוק את מה שקיים בפועל בקוד לפני שאתה יוצר משהו חדש.
- קיימת גם אפליקציה נייטיבית (Android/iOS דרך Capacitor) עם Firebase Messaging משלה — **אל תיגע בה ואל תשנה אותה**, המשימה הזו היא Web בלבד.
- טרם בוצעה אף שליחת push מוצלחת בפועל למכשיר כלשהו — לא Web, לא native.

## המטרה
כאשר משתמש שולח הודעה למשתמש אחר דרך האתר (למשל Owner → Coach, Coach → Trainee וכו'), המשתמש המקבל יקבל Push Notification אמיתי במכשיר שלו, גם כאשר האתר אינו פתוח.

## חשוב מאוד
- להשתמש ב-Firebase Cloud Messaging (FCM) עבור Web Push.
- להשתמש ב-Supabase עבור שמירת ה-FCM tokens והלוגיקה של המשתמשים.
- להשתמש ב-Supabase Edge Function לשליחת ההתראה בצורה מאובטחת.
- לא לשמור Firebase Server Key / credentials בתוך הקוד של האתר.
- לא להשתמש בשירות Push חיצוני בתשלום.
- לא לשנות או לשבור את המערכת הקיימת.
- קודם לבדוק מה כבר קיים בפרויקט ולבנות על הקוד הקיים במקום ליצור מערכת כפולה.

## מה צריך לממש

### 1. הרשאת Notifications
- כאשר המשתמש מחובר, לאפשר לו לתת הרשאה לקבלת Notifications.
- אם כבר קיימת הרשאה, לא לבקש שוב.
- אם המשתמש דחה, להציג מצב מתאים ולא ליצור לולאת בקשות.
- לשמור את סטטוס ההרשאה בצורה נכונה.

### 2. Firebase Web Push
- להגדיר Firebase Messaging עבור Web.
- ליצור/להשתמש ב-Service Worker הנדרש עבור Firebase Messaging.
- לקבל FCM registration token מהמכשיר/דפדפן.
- לטפל ב-token refresh (זו נקודה שידוע שחסרה כרגע במערכת — לוודא שיש listener ייעודי, לא רק קריאה בזמן setup ראשוני).
- לשמור את ה-token ב-Supabase כשהמשתמש מחובר.

### 3. Database
בדוק את הסכמה הקיימת לפני יצירת טבלאות חדשות — טבלת `push_tokens` כבר קיימת, כנראה אפשר לעבוד איתה כמו שהיא.

אם צריך טבלה חדשה, עם קשר למשתמש:
- user_id
- token
- platform/browser information אם צריך
- created_at
- updated_at

צריך לאפשר למשתמש אחד להיות מחובר ממספר מכשירים/דפדפנים, ולכן לא להגביל משתמש ל-token אחד בלבד.
צריך למנוע duplicate tokens.
**חשוב:** אם קיימת כיום לוגיקה שמוחקת את כל הטוקנים של משתמש כשהוא מכבה התראות במכשיר אחד — לתקן כך שתימחק רק שורת הטוקן של המכשיר הנוכחי.

### 4. Supabase Edge Function
בדוק את `send-fcm-notification` הקיימת (v17) לפני שאתה יוצר פונקציה חדשה — סביר שאפשר להרחיב אותה.

ה-Edge Function צריכה:
- לקבל recipient/user ID
- לקבל title
- לקבל body
- לקבל data אופציונלי
- למצוא את כל ה-FCM tokens הפעילים של המשתמש המקבל
- לשלוח את ההתראה דרך Firebase FCM
- לטפל ב-tokens לא תקינים ולהסיר אותם במידת הצורך

כל credentials/secrets הנדרשים לשליחה צריכים להיות Supabase secrets בלבד.

### 5. Chat → Push
חבר את מערכת ה-Push למערכת הצ'אט הקיימת.

כאשר משתמש שולח הודעה:
- לשמור את ההודעה כרגיל במערכת הקיימת.
- לזהות את המשתמש המקבל.
- להפעיל את מנגנון ה-Push.
- המקבל יקבל Notification עם שם השולח ותוכן קצר של ההודעה.
- לחיצה על ההתראה צריכה לפתוח את האתר ולעבור למסך/שיחה הרלוונטית אם הדבר אפשרי במבנה הקיים.

**חשוב גם:** ה-UI צריך להראות בבירור הבדל בין "ההודעה נשמרה" לבין "ה-push נשלח בהצלחה" — אלה שני מצבים נפרדים, לא להציג הצלחה לפני שה-push בפועל הושלם/נכשל.

### 6. Foreground / Background
צריך לתמוך בשני המצבים:
- האתר פתוח והמשתמש נמצא בו.
- האתר סגור / נמצא ברקע.

כאשר האתר פתוח, לא ליצור התראה כפולה אם כבר מוצגת הודעת צ'אט בתוך האתר.
כאשר האתר אינו פתוח, ה-Service Worker צריך לטפל ב-Push ולהציג Notification.

### 7. Security
חשוב במיוחד:
- לעולם לא לחשוף Firebase private credentials/client secrets של שליחה בצד הלקוח.
- השליחה ל-FCM חייבת להתבצע מהשרת/Edge Function.
- לא לאפשר למשתמש לשלוח Push arbitrary למשתמש אחר ללא הרשאה.
- להשתמש בהרשאות הקיימות של Owner / Coach / Trainee.
- לא לשנות RLS קיים אלא אם באמת הכרחי, ואם צריך שינוי להסביר לי בדיוק למה.

### 8. iPhone / Safari
אני רוצה שהמערכת תעבוד גם ב-iPhone ככל שה-Web Push של הדפדפן תומך בכך.

בדוק במיוחד:
- Safari / iOS Web Push
- Add to Home Screen / PWA במידת הצורך
- Service Worker
- Notification permission
- FCM Web compatibility

אל תניח ש-FCM Web עובד בדיוק אותו דבר ב-iPhone כמו Chrome Android. אם יש מגבלה ספציפית של iOS/Safari, תסביר לי אותה ותממש את הדרך הנתמכת הטובה ביותר.

### 9. Configuration
בדוק מה כבר קיים בפרויקט עבור:
- Firebase config
- VAPID key
- Firebase Messaging
- Service Worker
- Supabase
- Edge Functions
- environment variables

אל תיצור credentials פיקטיביים.
אם חסר משהו שאי אפשר ליצור מתוך הקוד, עצור את החלק הזה וסכם לי בדיוק מה אני צריכה לעשות ידנית ב-Firebase/Supabase, במילים פשוטות.

### 10. בדיקות — עם דרישת הוכחה מפורשת
**כלל מחייב: אף אחת מהבדיקות הבאות לא נחשבת "עברה" רק כי הקוד נראה תקין או שאין שגיאות בלוג. צריך תוצאה בפועל, מתועדת.**

- בדוק שה-token נוצר ונשמר — **הראה לי את השורה בפועל בטבלה** (user_id, platform, timestamp).
- בדוק שה-Edge Function נפרסת ועובדת — **מספר גרסה + תוצאת קריאת טסט אמיתית**.
- בדוק שליחת Push למשתמש ספציפי — **תוצאת OAuth מול Google בפועל (קוד 200 + access token), לא הנחה שזה עובד**.
- בדוק foreground.
- בדוק background — **עם הטאב סגור לגמרי, לא ממוזער**.
- **בדוק שהתראה מגיעה כשהמכשיר נעול לגמרי (מסך כבוי, לא רק טאב לא פעיל) — זו הבדיקה הקריטית ביותר בכל הרשימה. בלעדיה, אסור להצהיר שהמערכת "עובדת".**
- בדוק logout/login.
- בדוק מספר מכשירים לאותו משתמש.
- בדוק invalid/expired token.
- בדוק שאין duplicate notifications.
- בדוק שהודעות הצ'אט הקיימות עדיין עובדות.

חשוב:
- אל תבנה מחדש את מערכת הצ'אט.
- אל תשנה UI שלא צריך לשנות.
- אל תוסיף שירותים בתשלום.
- אל תמציא API keys או credentials.
- **אם אין לך גישה למכשיר פיזי אמיתי (טלפון/מחשב) כדי לבצע את בדיקת המכשיר הנעול — תגיד לי את זה במפורש, ואל תדווח "עובד" על בסיס קוד בלבד. עצור ותבקש ממני לבצע את הבדיקה בעצמי לפי הוראות שתיתן לי.**

## בסוף העבודה תן לי סיכום קצר מאוד ובשפה פשוטה:
1. מה כבר עבד.
2. מה הוספת.
3. מה עדיין חסר.
4. בדיוק אילו פעולות ידניות אני צריכה לבצע ב-Firebase/Supabase, אם יש.
5. **האם כרגע Push יכול להגיע לטלפון כשהאתר סגור — ואם התשובה מבוססת על בדיקה אמיתית שבוצעה, או על הערכה בלבד. אלה שני דברים שונים ואסור לערבב ביניהם.**
6. האם זה עובד ב-iPhone ומה התנאים לכך.
7. איך אני יכולה לבדוק את זה בפועל עם Owner ו-Coach, שלב אחר שלב.
