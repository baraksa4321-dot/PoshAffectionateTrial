My Routine — שינוי שם האפליקציה + מערכת אירובי

אני רוצה לבצע עכשיו שני שינויים באפליקציה הקיימת, בלי לבנות אותה מחדש ובלי לשנות את הארכיטקטורה הקיימת.

1. שינוי שם האפליקציה

שם האפליקציה הוא:

My Routine

צריך להחליף את השם הקודם GymTrack ל־My Routine בכל המקומות שבהם הוא מוצג למשתמש.

יש לבדוק ולעדכן:

* שם האפליקציה
* Logo / Branding, במקומות שבהם שם המוצר מופיע
* Login
* Navigation
* Dashboard
* כותרות עמודים
* Browser title / document title
* Metadata
* מסכי Loading
* Empty states
* הודעות מערכת
* טקסטים פנימיים שמציגים את שם המוצר

חשוב:

* לא לשנות שמות טבלאות או מבני Supabase רק בגלל שינוי השם.
* לא לשנות URLs או routes אם אין צורך אמיתי.
* לא לשבור imports או קוד קיים.
* חפש גם מופעים של GymTrack בקוד וב־UI כדי שלא יישארו אזכורים ישנים למשתמש.

המטרה היא שמבחינת המשתמש המוצר יוצג באופן עקבי בשם:

My Routine

⸻

2. מערכת אימוני אירובי

אני רוצה להוסיף ל־My Routine מערכת Cardio Training מלאה, שתהיה זמינה לכולם — במיוחד ל־Client שיוכל להוסיף לעצמו אימון אירובי.

הוספת אימון אירובי

צריך להוסיף פעולה ברורה:

Add Cardio Workout

המשתמש יוכל לבחור סוג פעילות מתוך מאגר רחב.

לדוגמה:

* Walking / הליכה
* Running / ריצה
* Treadmill / הליכון
* Cycling / אופניים
* Stationary Bike / אופני כושר
* Elliptical / אליפטיקל
* Stair Climber / סטפר
* Swimming / שחייה
* Tennis / טניס
* Basketball / כדורסל
* Football / כדורגל
* Hiking / הליכה/טיול
* Rowing / חתירה
* Jump Rope / קפיצה בחבל
* HIIT
* Aerobics
* ועוד סוגי אירובי נפוצים.

המטרה היא שלא יהיו רק 3–4 אפשרויות, אלא ספריית פעילויות שימושית באמת.

Duration

לאחר בחירת הפעילות המשתמש יוכל להזין:

Duration

לדוגמה:

* 20 min
* 30 min
* 45 min
* 60 min

חישוב קלוריות אוטומטי

המערכת צריכה לחשב אוטומטית את Estimated Calories Burned.

החישוב צריך להשתמש, ככל שהמידע קיים במערכת, ב:

* סוג הפעילות
* משך הפעילות
* משקל המשתמש
* עצימות / קצב, אם קיימים נתונים מתאימים

לדוגמה:

Running · 30 min
Estimated calories burned: XXX kcal

חשוב שהערך יהיה חישוב מבוסס ולא מספר אקראי.

יש להציג אותו כ־Estimated calories burned, מכיוון שמדובר בהערכה אלא אם קיימת מדידה אמיתית ממכשיר.

שמירת נתונים

אימון אירובי חייב להישמר כמו שאר נתוני המשתמש:

Add → Save → Supabase → Refresh → עדיין קיים

וגם:

Add → Save → Logout → Login → עדיין קיים

הפעילות צריכה להופיע בהיסטוריה במקום המתאים.

Client

המתאמן צריך להיות מסוגל:

* להוסיף אימון אירובי לעצמו
* לבחור פעילות
* להזין משך
* לראות חישוב קלוריות
* לשמור
* לראות את הפעילות בהיסטוריה

Coach

Coach צריך להיות מסוגל לראות את אימוני האירובי של המתאמנים המשויכים אליו, בהתאם להרשאות ול־RLS הקיימים.

Owner

Owner צריך להיות מסוגל לראות את נתוני האירובי בהתאם להרשאות הניהול הקיימות.

UI

מערכת האירובי צריכה להיות:

* פשוטה וברורה
* Mobile-friendly
* RTL-friendly
* עקבית עם העיצוב של My Routine
* ללא Water UI

Supabase

לפני כל שינוי במסד הנתונים:

1. בדוק אם הסכמה הקיימת כבר יכולה לתמוך באימוני אירובי.
2. אם כן — השתמש במבנה הקיים.
3. אל תיצור טבלאות כפולות.
4. אל תשנה RLS ללא צורך.
5. אם באמת נדרש שינוי schema, עצור ודווח בדיוק:
    * מה חסר
    * למה הוא נדרש
    * איזה Table/Column צריך להשתנות
    * כיצד RLS יגן עליו

אל תבצע שינוי DB משמעותי רק כדי להוסיף את הפיצ’ר.

בדיקות

בסיום:

* npm run build
* npm run lint
* בדיקת Mobile
* בדיקת RTL
* בדיקת UI
* בדיקת שמירה אם קיימת אפשרות לאינטראקציה אמיתית

בדוח הסיום הפרד בין:

FIXED
VERIFIED — נבדק בפועל בדפדפן
CODE VERIFIED — אומת בקוד בלבד
NOT VERIFIED — לא ניתן היה לבדוק בפועל
DATABASE CHANGES
SECURITY
PERSISTENCE

אל תטען שהשמירה, חישוב הקלוריות או הרשאות ה־Roles נבדקו בפועל אם לא הייתה אפשרות לבצע אינטראקציה אמיתית.
