GymTrack — בדיקה ותיקון של 3 בעיות פתוחות

יש כרגע שלוש בעיות שצריך לטפל בהן באותה משימה:

1. maya2003yos עדיין מזוהה כ־Owner.
2. חלונות/כרטיסיות שנפתחים בלחיצה עדיין נפתחים למטה בתוך העמוד במקום מעל התוכן.
3. החזרות עדיין לא מוצגות/נשמרות כטווח, ואני צריכה תמיכה אמיתית ב־8–12.

1. Maya2003yos — Owner

אחרי Logout מלא והתחברות מחדש עם:

maya2003yos

האפליקציה עדיין מציגה את המשתמש כ־Owner.

לפני כל שינוי

אל תשנה:

* role
* RLS
* migration
* is_owner()
* change_user_role()
* Supabase schema

קודם בדוק את המקור האמיתי.

בדוק:

* Auth user ID של Maya.
* profiles.role.
* profiles.coach_id, אם קיים.
* מה is_owner() מחזיר עבור המשתמש.
* איזה role ה־UI מקבל ומציג.

השווה:

DB role → is_owner() → app role → displayed role

אם profiles.role = owner

עצור.

אל תשנה את התפקיד.

דווח לי שה־DB עצמו מגדיר אותה כ־Owner ואני אחליט מה צריך להיות התפקיד הנכון.

אם profiles.role != owner

מצא למה האפליקציה עדיין מציגה Owner.

בדוק במיוחד:

* session hydration
* cached profile
* stale state
* is_owner()
* fallback role
* dashboard routing
* localStorage/session state

אל תתקן באמצעות hardcoded תנאי עבור Maya.

2. Exercise Picker / כל חלון שנפתח בלחיצה עדיין מופיע למטה

הבעיה עדיין קיימת בפועל.

לדוגמה:

* בחירת מאכל.
* החלפת מאכל.
* בחירת תרגיל.
* חלונות בחירה נוספים.

במקום להיפתח כ־Dialog/Sheet מעל המסך, הם עדיין יכולים להופיע למטה בתוך ה־page flow.

אל תסתפק בבדיקת קוד

צריך למצוא למה זה קורה בפועל.

בדוק:

* Portal ל־document.body.
* position: fixed.
* inset.
* z-index.
* stacking contexts.
* transform.
* overflow.
* contain.
* parent wrappers.
* CSS של ה־Sheet.
* האם רכיב ישן עדיין מוצג במקום רכיב ה־Radix החדש.
* האם קיימים שני רכיבים במקביל ורק אחד מהם הוא זה שאני רואה.

חשוב

אם אפשר לבצע בדיקת browser אינטראקטיבית:

פתח בפועל את:

Nutrition → Choose Food

ואז:

Nutrition → Replace Food

ואז:

Program/Workout → Add Exercise

ובדוק איפה החלון מופיע.

אני רוצה שהחלון:

* יופיע מעל כל התוכן.
* לא ייכנס ל־flow של העמוד.
* לא יידחף לתחתית.
* יהיה עם overlay ברור.
* יאפשר גלילה פנימית.
* ינעל את גלילת העמוד.
* ייסגר ב־X.
* ייסגר ב־Escape.
* ייסגר ב־click outside.
* יעבוד במובייל.
* יעבוד ב־RTL.

אל תכתוב “fixed” רק משום שהקוד מכיל position: fixed.

הבדיקה צריכה להיות של מה שמופיע בפועל בדפדפן.

3. Rep Range — החזרות חייבות להיות טווח

אני לא רוצה רק שדה של מספר חזרות.

אני רוצה תמיכה אמיתית ב:

Fixed

לדוגמה:

10

Range

לדוגמה:

8–12

צריך להיות אפשר:

1. לבחור Rep Type = Range.
2. להזין Min = 8.
3. להזין Max = 12.
4. לשמור.
5. לראות בתוכנית/אימון 8–12.
6. לעשות Refresh.
7. לראות עדיין 8–12.
8. Logout.
9. Login מחדש.
10. לראות עדיין 8–12.

בדוק את כל השרשרת:

UI → state → save → Supabase → reload → display

בדוק במיוחד שהמערכת לא עושה:

8–12 → 8

או:

8–12 → 12

או מציגה Range אבל שומרת רק reps.

Validation

* Min חייב להיות תקין.
* Max חייב להיות תקין.
* Min לא יכול להיות גדול מ־Max.
* Range צריך להישמר כ־repType + repMin + repMax.
* אין ליצור עמודות DB חדשות אם המבנה הקיים כבר מספיק.

⸻

אסור לשנות את ה־role שלה לפני שאני מאשרת.
